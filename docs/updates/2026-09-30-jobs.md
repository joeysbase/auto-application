# Dedup writes jobs (C8c) — 2026-09-30
**Step:** 1   **Status:** done

## What
- `src/auto_app/process/link.py`: **incremental** linking of new postings (normalized, not yet linked) to jobs:
  1. Level 1b against earlier same-source postings (existing or new) → `duplicate_of`, joins that job.
  2. Level 2 grouping among new postings (same rules and merge vetoes as the preview), then each group joins the best-matching **existing** job — vetoes checked against every posting of that job — or becomes a new job.
  3. Existing jobs keep their ids and **status**; jobs that gained postings get an updated primary posting (company source > external apply > Easy Apply), canonical URL, company/title, first/last seen, `job_keys` (employer key, company|req id, description hash, company|title fingerprint) and `job_locations`.
  4. Postings record `match_rule` / `match_confidence`, state `linked`. Parse and normalize treat `linked` as already processed; re-normalizing a linked posting keeps it linked.
- `DbStore`: job methods (create/update/link, keys, locations, listing, members), one transaction per dedup run, `clear_jobs`.
- CLI: `auto-app dedup` writes; `dedup --preview` is a dry run of the same plan; `dedup --rebuild` regroups from scratch, **refused** once any job is beyond `collected`; `auto-app jobs [ID] [--status]`; `inspect` shows a posting's job.
