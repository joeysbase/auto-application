# Database (C7) — 2026-09-30
**Step:** 1   **Status:** done

## What
- **Storage interface** (`collect/store.py`): every stage (collect, parse, normalize, dedup, `inspect`, `stats`) now goes through one set of store methods, addressing postings as `PostingRef(source, job_id)` instead of folders. Search runs are started/finished through the store (`start_search_run` / `finish_search_run`), so the database assigns their ids.
- **`DbStore`** (`core/db/store.py`): SQLite (`data/auto_app.db`, WAL, foreign keys) via SQLAlchemy Core. Tables per Step 1 §8.2 — batches, search runs, search results, source health, postings (identity, state, parsed + normalized JSON with indexed key columns), `posting_raw` (zstd-compressed page text/HTML/JSON/records), and the C8c tables (jobs, job_locations, job_keys, company_aliases), created empty.
- **Migrations**: Alembic (`migrations/`), applied automatically when the database opens; the initial migration creates all 10 tables.
- **Files as a debug option**: `FileStore` (the old `data/raw/` layout) stays as a full implementation. `--debug-files` (or `debug_files: true` in the config) mirrors every posting/batch write to files; `export <source> <id>` writes one posting; `import-files` loads a file store into the database (idempotent; renumbers search runs and remaps postings' run references; copies logs and failure artifacts).
- Logs moved to `data/logs/<batch>.log`, screenshots to `data/screenshots/`, block artifacts to `data/failures/`. CLI `--out` (file root) replaced by `--db` (database file).

## Fix found on the way
`parse` treated a normalized posting as not-yet-parsed (it only skipped state `parsed`), so every `parse` run re-parsed normalized postings, which then triggered a re-normalize. Now postings in `parsed` or `normalized` with the current parser version are skipped.
