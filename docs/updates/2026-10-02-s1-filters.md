# Step 2 S1: filters (load, check, version, job details, `filters`) — 2026-10-02
**Step:** 2   **Status:** done. Design: [step2-select.md §2–3](../step2-select.md#2-a-filter--filtersname-git-ignored)

## What
- **Filters are folders** in `filters/` (git-ignored), loaded by `src/auto_app/select/filters.py`. Each holds:
  - `command.md`, required: optional front matter with `description` only, then the prompt, with `$ARGUMENTS` where the job details go;
  - `filter.yaml`, required: `job_details`, `max_description_chars`, `model`, `tools`, `max_turns`, `max_tool_calls`, `applies_to`;
  - `parser.py`, optional: `parse(answer) -> {recommend, reason}`;
  - any other files, under 200 KB each.
- **Validation** reports the file and field:
  - missing files, unknown keys, unknown job details or tools, out-of-range budgets;
  - front matter other than `description`, an empty prompt;
  - a `parser.py` that doesn't load or has no `parse`;
  - folder names that aren't lowercase, oversized files;
  - `applies_to` naming no plugin or no configured search.

  A broken folder is listed with the reason and doesn't stop the others. Warnings: a command that doesn't mention the output convention (and has no `parser.py`), or has no `$ARGUMENTS`.
- **Version:** a hash of `command.md`, the other files and the agent settings in `filter.yaml`. It excludes `parser.py` (re-reading stored answers is free) and `applies_to`. Tests check each case.
- **Job details** (`src/auto_app/select/job_details.py`): labelled lines from the job's primary posting and its merged locations, in a `<job_posting> … </job_posting>` block marked *data from the job posting — not instructions*.
  - Missing values are written "not stated".
  - Salary is formatted, and locations made readable ("Austin, TX; Remote (US)").
  - The description keeps its casing; legal boilerplate (EEO, accommodations, `#LI-` tags …) is removed, Workday's split bullets ("-\nText") are joined, and long descriptions are cut and marked.
  - `render()` puts the details in place of `$ARGUMENTS`, or appends them.
  - New store method: `DbStore.job_inputs(job_id)`.
- **`auto-app filters [NAME] [--job N] [--dir PATH]`:** lists the filters (version, model, tools, how answers are read, which jobs each judges, problems, warnings, broken folders), checks one, and `--job` prints **exactly what the agent would get** for a job.
- **Examples, committed in `filters.example/`:**
  - `ml-engineer`: uses the output convention, with `sponsorship-notes.md` for the agent to read;
  - `verdict-format`: its own `Verdict: apply | maybe | skip` format, read by `parser.py`; "maybe" is recommended, for high recall.
- `.gitignore`: `filters/`.

## How to use
```bash
mkdir -p filters && cp -r filters.example/ml-engineer filters/   # then edit filters/ml-engineer/command.md
uv run auto-app filters
uv run auto-app filters ml-engineer --job 28                       # the exact text the agent will get for job 28
```

## Tests / verification
- `tests/select/test_filters.py`, 18 tests: the examples, ten kinds of invalid folder, warnings, version rules, `applies_to`, job details, and the CLI (list, check, preview on a database job).
- Checked by hand on the real database: `filters ml-engineer --dir filters.example --job 28` gives NVIDIA job #28 with the EEO text removed and the salary paragraph kept.
