# Web frontend W2: decide and label in the browser — 2026-10-07

The web app's Jobs page now does what the TUI's Jobs section does, through the same code (`Review` / `JobBrowser`).

- **API:**
  - `POST /api/jobs/{id}/decide` (want_to_apply / not_applied, with a reason);
  - `POST /api/jobs/{id}/label` (one filter, or every filter; with a reason);
  - `POST /api/jobs/{id}/mark` (any state);
  - `POST /api/jobs/{id}/reason` (your last answer on the job);
  - `POST /api/undo`.

  Each returns a message, the job as it is now, and whether undo has something. Refusals are 400s with the
  reason. One lock serializes answers. `GET /api/jobs?keep=` keeps answered jobs listed in their tab.
- **The page:**
  - answer buttons on the job and on each verdict;
  - the TUI's keys (`a n g b B m r u`, `←` `→` / `1`–`9` to pick a filter);
  - a state menu and a reason box;
  - a toast with "add a reason" and "undo";
  - after `a` / `n`, the next job opens, and the answered job stays dimmed in the tab until you leave it.
- **Fixed:** `JobBrowser.add_reason` crashed after `B` (every filter labelled at once). The reason now goes on
  each of those labels, which fixes the TUI's `r` too.
- **Docs:** `docs/web-frontend.md` §7 and the README `web` section. The `/auto-app` skill says the web app can answer
  too.

**Tests:** `tests/test_web.py` (9):
- decide, labels, mark, reasons and undo through the API;
- the browser test answers with `n`, `r` and `u`, and checks the database.
