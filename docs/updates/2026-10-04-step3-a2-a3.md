# Step 3 A2 + A3: question answering, the Needs input tab, the Greenhouse applier — 2026-10-04
**Step:** 3   **Status:** done. Tested offline. Filling checked on a **real** Greenhouse form; nothing was submitted.

## What
- **Answering questions (A2).** Each question is classified, answered from a source, and given a confidence:
  - **standard** fields (name, email, phone, CV, country, links, city) come from `profile.yaml`;
  - **known** questions come from `answers.yaml`: an exact question match first, then **Claude** picks the entry that means the same, with a confidence (threshold `AUTO_APP_APPLY__MATCH_THRESHOLD`, 0.9);
  - **sensitive** questions (authorization, sponsorship, citizenship, demographics, legal agreements) come **only** from an `answers.yaml` entry, never drafted or guessed;
  - **free text** comes from a saved free-text answer (`{company}` / `{title}` filled in; `adapt: true` makes it a draft), else is **drafted by Claude**, marked ✎ and shown in review;
  - **dropdowns** are mapped onto the listed options.
  
  Optional questions with no answer are left blank.
- **Claude** runs through the Claude Code CLI with your login: one call per application, no tools, a fresh session, nothing saved, no API key. If it fails, the questions go to you.
- **The Greenhouse applier (A3):**
  - **prepare:** reads the questions from the public job board API (no browser), adds the form's Country field, answers them, and parks the job in **Needs input** or **Ready to submit**. A closed posting (404) stops.
  - **submit:** fills the hosted form in Chrome. The CV goes first, because Greenhouse refills name / email from it; then text and React dropdowns (keyboard-open, click the option); text is re-checked at the end. It clicks submit and waits for the confirmation.
  - **Outcomes:** a CAPTCHA → **Action needed** (solve it in a visible browser, then `s` again); a form it can't fill → the next applier (Simplify); `f` **fill only** leaves a filled browser for you to submit.
- **Inbox tabs:**
  - **Needs input:** `enter` answer the ▸ question, `A` for every job waiting with it, `S` and save it to `answers.yaml`;
  - **Action needed;**
  - **Ready to submit:** every answer with its source; `s` submit, `f` fill only, `e` edit, `a` applied.
  
  The Inbox opens on the first tab with something in it. Submitting runs in the background; the section bar counts each tab.
- **Settings:** `AUTO_APP_APPLY__MODEL`, `__MATCH_THRESHOLD`, `__HEADLESS`, `__CLAUDE_CLI`. A `questions` table (migration `b3a4bc3f1837`).

## Checked on a real form
On `job-boards.greenhouse.io/anthropic/jobs/4461450008`, with the example profile and **no submit**, every field ended up right: text, the CV upload, Country, yes/no questions, the agreements and demographics. Three fixes came from that check:
1. **Dropdowns** need the page fully loaded, and are opened with the keyboard.
2. **The option list** must be the menu's visible `role="option"` entries, not a plain `<select>`'s hidden options; "United States" matches "United States +1".
3. **Order matters:** the CV goes first, and text is re-checked at the end.

## Fixed: `q` didn't give the terminal back while `R` was starting jobs
- **The problem:** after `R`, quitting closed the screen, but the process waited for the background start to finish (Claude calls, possibly minutes). It looked like `q` didn't work.
- **Starting jobs now runs in a daemon thread,** so quitting never waits; jobs that didn't start stay queued for the next `R`. Measured: back to the shell in 0.3 s instead of after the start finished.
- **During a submission** (a browser filling and submitting a form), `q` warns once ("press q again to quit anyway") instead of cutting it off silently.
- Test: `test_quitting_never_waits_for_starting_jobs_and_warns_during_a_submission`. 280 tests pass.
